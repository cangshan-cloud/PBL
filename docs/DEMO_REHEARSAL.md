# 十分钟课程演示与会前就绪检查

本稿供成员 D 组织彩排、队长统一提交；它不是任何成员已经完成彩排或个人验收的证明。现场优先展示仓库自带的合成 `demo_daily`，因为它可随 Git 离线复现；真实沪深 300 私有包仅在已提前核验并发布的 Mac 环境中作为可选加分演示，不能让演示依赖临时网络采集。

## 会前只读预检（不计入十分钟）

启动服务后，先在宿主机打开 `http://localhost:5173/`，并访问 `http://127.0.0.1:8000/health`。`docker compose ps` 的 `healthy` **不能代替**宿主机访问测试。然后为三种账号设置 `FACTORLAB_DEMO_ADMIN_PASSWORD`、`FACTORLAB_DEMO_RESEARCHER_PASSWORD`、`FACTORLAB_DEMO_VIEWER_PASSWORD` 环境变量；不要把实际密码写入截图、日志或 Git。仅在全新本机演示环境中，密码可使用 README 中的默认值。运行：

```bash
python3 tools/check_demo_readiness.py
# 只有计划展示本机历史私有包时再加：
python3 tools/check_demo_readiness.py --require-historical
```

脚本只登录并读取账号角色、已发布 `demo_daily` 0.2.0（2,400 行／20 只股票）、六因子目录，以及查看者可读的任务/报告列表；可选检查平台目录中有已发布的历史包。它**不创建任务、不重算因子、不验证历史包文件存在性**。若端口访问、账号或数据检查失败，先停止彩排并记录环境与错误；不要现场反复重装、删卷或重置数据库。需要验证 Worker 与报告时，再在隔离或允许留下验收记录的环境运行 `tools/verify_compose_stack.py`，该脚本会创建任务。

2026-10-14 实测：只读预检在独立 SQLite API 上通过；`--require-historical` 在未发布历史包时按预期失败。同日原有 `fbl` OrbStack 容器显示健康，容器内 `/health` 返回 200 且端口映射存在，但 Mac 宿主机访问 `127.0.0.1:8000` 和 `localhost:8000` 均被拒绝。当前**不能**把原有 Compose 栈标为演示就绪；在正式彩排前需恢复并重新实测宿主机端口。此次没有重启或改动原有容器。

## 现场十分钟剧本

| 时间 | 操作 | 应看到的证据 | 失败时的收束 |
| --- | --- | --- | --- |
| 0:00–0:45 | 说明范围：少量研究人员、沪深 A 股日频、课程研究，不交易 | 平台/产品分层与研究风险边界 | 不在现场新增范围 |
| 0:45–2:00 | 管理员登录，打开数据集与因子库 | `demo_daily` 已发布，2,400 行、20 只虚拟股票；六因子公式可见 | 使用事先保存的离线截图说明，并标为演示降级 |
| 2:00–4:00 | 研究员运行演示数据 20 日动量、五分组、10 bps | 任务成功，约 1,980 个有效观察、99 个 IC 截面；实际数字以运行结果为准 | 若 Worker 无响应，展示先前成功任务，不伪造本次执行 |
| 4:00–5:30 | 打开任务中心 | 数据/因子/代码版本、参数、日志与结构化结果；下载复现 JSON | 若新任务失败，展示日志和失败原因 |
| 5:30–6:45 | 打开报告中心 | HTML 报告、IC 与净值图、报告下载和摘要校验和 | 使用同版本先前报告，说明是历史任务 |
| 6:45–8:00 | 可选：历史沪深 300 任务与审计 | 历史包清单、四因子审计；两份 CSV 可与复现 JSON 核对 | 私有包未就绪时跳过，不临时采集、不把合成数据说成真实数据 |
| 8:00–9:00 | 切换只读角色并说明权限 | 可查看任务与报告，不可创建研究或导入数据 | 展示权限矩阵与自动测试结果 |
| 9:00–10:00 | 总结限制与答问缓冲 | 结果为样本内研究；停牌、成本、成分时点和 Windows 部署边界明确 | 到 10 分钟主动收束 |
