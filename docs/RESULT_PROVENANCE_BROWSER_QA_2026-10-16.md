# 工作台结果归属与分组口径浏览器验收（2026-10-16）

## 问题与范围

研究工作台原先保留最近一次任务结果，但因子、数据版本、样本日期、证券、分组或预处理改变后，旧指标仍位于新配置下方；未运行时还把五组收益显示为 `0.00%`。这可能让研究人员误把旧任务或“未计算”当作当前结果。本轮只调整前端结果展示与历史审计下载的任务绑定，不改变因子公式、数据库结果或报告算法。

## 实现与判定

- `frontend/src/main.tsx` 将提交给 API 的研究参数与研究模式组成配置键；任务仅在该键与当前表单一致时展示。参数与展示共用同一对象，避免两套口径漂移。
- 每次新运行先清空旧工作台结果，并把新任务与当次配置键绑定；运行后显示 Run ID、数据版本、任务状态。修改配置后隐藏旧指标和图表，提示旧任务可在任务中心按 Run ID 查阅；恢复相同配置时可再次查看其对应结果。
- 尚未运行或没有有效分组日期时不制造 `0.00%` 条形图；前者显示“未计算不代表零收益”，后者说明空值。
- 多空标签按当前分组数量显示 `Qn − Q1`，任务中心的标题改为不预设五组的“分组平均收益”。
- 历史审计 CSV 下载使用工作台当前历史任务的 Run ID，而非任务中心上次选中的 Run ID。此处已做代码核对与前端构建，**未**在本轮用私有历史包触发浏览器下载；相关后端接口由既有自动测试覆盖。

## 本轮验证

实际执行者：Codex。Mac 上以独立临时 SQLite、FastAPI 内联任务模式及 Vite 启动隔离浏览器，使用内置合成 `demo_daily` 0.2.0：

1. 初始工作台指标为破折号，分组区提示“尚无当前配置的分组结果”，没有虚构五组零收益。
2. 运行 20 日动量、五分组任务 `a2f2d77b-d40a-4d7c-a133-988d2efba9e2` 成功；工作台显示 Run `a2f2d77b` 和 0.2.0 数据版本。
3. 将因子切换为 5 日反转后，旧任务指标变为破折号，图表隐藏，页面显示配置变化提示；旧任务仍在任务中心。
4. 将分组数设为 3 并新建任务 `6ccd7ea4-ec60-4f35-8825-85efdb3e3576` 成功；工作台显示新 Run、`Q3 − Q1` 和 Q1～Q3 结果，任务中心标题不再写死五组。
5. `npm run build` 通过；`make test` 后端 191 项通过；固定六观测黄金验算通过。浏览器控制台错误 0、警告 0。

## 边界

这是 Mac 隔离内联模式的前端行为验收，不是当前提交的五服务 Celery 重新验收、Windows 部署或正式十分钟讲解。没有使用本机私有历史包执行审计 CSV 浏览器下载；正式演示前若展示历史模式，应另做该按钮的实际下载核对。队长本人产品测试仍待补。
