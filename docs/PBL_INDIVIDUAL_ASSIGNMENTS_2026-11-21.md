# 四人独立 PBL 作业总索引（2026-11-21）

## 1. 使用说明

本批材料按 [`TEAM_MODULE_DIVISION_2026-11-20.md`](TEAM_MODULE_DIVISION_2026-11-20.md) 的 M1—M4 功能模块设计。四人各有 PBL1 作业1、PBL1 作业2、PBL2 作业1、PBL2 作业2，共 16 份独立 Word 文档。文档沿用教师模板和评分表；模板中的蓝字任务说明已替换为对应模块题目，答案正文、模型图、架构图、伪代码、数据/接口模型及验收用例均已写入。

姓名、学号、班级、任课教师尚无可靠信息，因此封面统一保留 `【待填写：……】` 占位符。正式提交前只需填写这些基础信息并按课程要求复核页眉、文件命名和提交平台；不得把占位符当作已确认信息。

## 2. 四类作业统一提交物

| 作业 | 本批提交物定义 | 答案正文设计 |
| --- | --- | --- |
| PBL1 作业1 | 1—2 页设计说明 + 相关模型图（流程图、时序图或状态机等） | 采用 2 页：核心单元、典型流程模型、交互求解、关键接口与异常处理 |
| PBL1 作业2 | 2 页设计文档 + 架构图 + 关键算法伪代码或数据模型 | 采用 2 页：问题与目标、组件架构、职责、伪代码、接口模型、可行性 |
| PBL2 作业1 | 2—3 页产品方案 + 业务流程图 + 功能/非功能需求 + 验收用例 | 采用 2 页：业务逻辑、流程、需求、技术方案、用例、边界 |
| PBL2 作业2 | 2—3 页组件实现设计 + 组件架构图 + 接口契约 + 实现/测试要点 | 采用 2 页：业务单元、组件架构、技术选型、接口、伪代码、测试 |

PBL2 的提交物由项目组结合原模板自行确定，侧重把 PBL1 的设计进一步落到产品业务与软件组件，而不是重复同一份内容。

## 4. 责任与事实边界

- 题目和正文由组长口径统一设计，实际文档生成与本轮排版/自动核验执行者为 Codex。
- 四名成员的课程责任仍各占 25%，每人材料只陈述其功能模块，不把其他模块成果重复包装为个人独立实现。
- 本批文档是可提交初稿，不替代队长最终人工核对；成员无需另行签收，但提交人应确认封面信息、教师格式和文件上传结果。
- 文档中的真实样本、统计与风险表述只作为软件研发和课程验收证据，不构成投资建议，也不证明未来收益。
