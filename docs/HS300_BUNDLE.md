# 沪深 300 历史研究输入数据包

状态：本机离线封存与完整性复验通过；已在隔离平台环境完成注册、发布、历史研究任务、报告与审计验收。数据包在 `data/real/bundles/`，被 Git 忽略，原始行情不随仓库分发。其他机器需要自行取得同一数据包，不能仅靠 Git 仓库复现真实数据结果。

## 构建与复验

先完成[历史成员快照](HS300_DATA_FEASIBILITY.md)和[价格/状态快照](HS300_PRICE_STATUS.md)的源验证，再运行：

```bash
python tools/build_hs300_bundle.py
python tools/verify_hs300_bundle.py \
  data/real/bundles/hs300_2024_0375298bd2c8ac52
```

构建器再次验证源快照：2024 全年成员必须完整、价格快照必须覆盖全部成员日，缺行/未知交易或 ST 状态不允许通过；两份交易日历的 2024 交易日必须一致；价格日历须含至少 20 个正式期前交易日和期后下一交易日。它将来源清单、每日成员原始查询、逐证券价格/状态和两个日历**复制**进临时目录，计算每个文件 SHA-256 与内容地址，再原子地命名为 `hs300_2024_<哈希前缀>`。已有相同 ID 的目录不会被覆盖。

复验器检查目录与内容 ID、文件集合和逐文件 SHA-256，并在包内重新运行成员、价格及跨组件语义检查。这里的“不可变”指内容寻址、拒绝覆盖和使用前可检测篡改；文件系统本身并非写保护。

历史研究加载时先复验整包；随后每个真正参与解析的日历、逐日成员和逐证券行情 CSV 都从单次读取的字节中重新对照清单 SHA-256，再解析同一份字节。这样即使文件在整包复验与加载之间变化，也不会把新内容当作已核验内容参与计算。它不是文件系统锁或原子目录快照，不能防止并发恶意替换所有文件；私有包仍须存放在受控本机目录。每次只保留一个 CSV 的原始字节快照，不把全部 576 个文件同时载入内存。

## 使用边界

包保留 BaoStock `adjustflag=1` 后复权源价格；研究侧只能使用 `source_close`，不得叠加二次复权。成员生效时点已用 2024 年 12 月官方调样逐只交叉核验，但并非所有维护事件都获独立核验；ST 历史源状态也未获独立核验。后复权价可能随上游修订。平台可在**本机私有数据存在**时注册发布和执行专用历史任务；这不等于可信回测或可执行收益。
# 平台注册与发布（2026-10-13 新增）

封存包仍保留在 `data/real/bundles/<bundle_id>/`，不纳入 Git。API 的 `DATA_ROOT` 应指向同级 `data/runtime`；容器内分别为 `/data/real/bundles` 与 `/data/runtime`。管理员可调用 `POST /api/v1/datasets/register-hs300-bundle`，JSON 为 `{"bundle_id":"hs300_2024_0375298bd2c8ac52"}`。接口只接受固定格式的包 ID，不接受任意文件路径；成功后生成草稿版本。随后调用既有 `POST /api/v1/datasets/{id}/publish`，发布前重新核验清单摘要、内容身份、文件全集及每个文件的 SHA-256。重复注册、缺文件、多文件或内容篡改均会失败。

此阶段平台侧校验是**完整文件完整性核验**，并非重新执行离线采集脚本的所有业务语义校验；封存前的业务语义复验仍由 `tools/verify_hs300_bundle.py` 执行。历史包虽可注册和发布，但旧单 CSV 研究接口会明确拒绝它，不能把“已发布”理解为“历史因子研究已可运行”。历史研究专用计算链路是下一阶段工作。

历史研究任务加载价格行时还会拒绝 `close`、`turn`、`volume` 中的非有限数值（包括 `NaN`、`Infinity` 及浮点解析溢出），避免其绕过交易资格判断并污染因子/收益；空值仍按既有缺失规则处理。这是运行时的防线，不替代封存前业务语义复验，也不表示已认证行情来源或授权。

研究任务完成逐行加载后，会把实际 2024 成员交易日数、成员行数、价格证券数和价格行数与清单摘要逐项核对；不一致即拒绝计算。注册与发布阶段仍只做文件完整性核验，因此此运行时核对不意味着注册页面的摘要已经获得独立业务认证。

加载器还要求交易日历、逐日成员名单和逐证券行情 CSV 的表头与封存格式完全一致；即使文件哈希自洽，额外/缺失列或行宽不一致也会拒绝。空字段保留给后续缺失值与可交易性规则处理，不将“列存在”误读为“字段值有效”。

研究加载时逐行要求行情 `adjustflag=1`，与清单声明的后复权源价格一致；交易日历标记只能是 `0/1`，日期必须严格递增，未知标记或重复/乱序日期不再被静默跳过。这些检查只保证包内口径自洽，不证明 BaoStock 历史价格未修订或交易所日历已获独立核验。

逐日成员名单加载时还要求 300 个有效且不重复的 `sh.`/`sz.` 六位代码，`query_date` 与当日一致，`update_date` 为合法日期且不晚于查询日。它避免明显的未来日期泄漏；仅凭来源 `update_date` 仍不能证明全部指数维护事件在研究日已正式生效。

## 历史研究计算核心（2026-10-13）

`backend/app/domain/historical_research.py` 已实现平台内专用读取和四因子观察计算：用价格源的 292 个市场交易日做连续窗口，其中 43 个预热日仅作输入、2024 年 242 日作信号、2025 年初交易日仅作标签；t 日按当日成员、交易状态、ST 和成交量筛选，收益只取统一日历的 t+1，不跳到复牌日，股票次日退出指数也不事后删除 t 日信号。逐日审计记录非成员、停牌/ST、无有效成交、窗口缺失、标签不可用等计数。

本机私有包试算的有效收益观察：20 日动量 72,366、5 日反转 72,471、20 日波动率 72,366、20 日换手率 72,373。这些是**观察数量，不是收益表现或策略结论**。此处记录的是计算核心首次完成时的阶段状态；后续专用任务与逐行无标签审计见下一节。平台发布接口仍只做文件完整性校验，业务语义在历史计算加载时额外检查。

## 审计 CSV 导出（2026-10-14）

历史研究成功任务的研究工作台增加“下载逐日审计 CSV”和“下载无标签信号 CSV”。对应接口分别是 `GET /api/v1/research/tasks/{task_id}/historical-audit/daily.csv` 与 `.../unlabeled.csv`。前者按因子和日期展开候选、排除及有效收益计数；后者逐条列出有信号但无有效次日收益的日期、证券、因子值、次日市场日与原因。CSV 用 UTF-8 BOM 便于常见表格软件读取，缺少某项逐日计数按 0 展示；无标签明细为空时仍有表头。只有已完成且含历史审计的任务可下载，研究员只可下载本人任务，管理员及查看者沿用既有全局读取权限。该导出不重新计算指标，来源就是任务保存的结构化审计；不能将缺失标签误读为零收益。

将同一任务的“下载复现包”和两份审计 CSV 放在同一目录后，可用仅依赖 Python 标准库的工具独立核对文件间一致性：

```bash
python3 tools/verify_historical_audit_exports.py factor-run-XXXXXXXX.json historical-audit-daily-XXXXXXXX.csv historical-audit-unlabeled-XXXXXXXX.csv
# 若同时下载了 HTML 报告，可追加：
python3 tools/verify_historical_audit_exports.py factor-run-XXXXXXXX.json historical-audit-daily-XXXXXXXX.csv historical-audit-unlabeled-XXXXXXXX.csv --report-html factor-report-XXXXXXXX.html
```

工具先按复现包的规范 JSON 序列化口径重算并核对 `result_sha256`，再检查列头、逐行内容、因子逐日汇总与无标签信号数量；不需要私有行情包。2026-10-14 用本机真实包试验得到 4 个因子、968 行逐日记录、32 条无标签信号，且上述一致性检查通过。结果摘要可以发现 JSON 的意外改动，但它不带密钥，JSON 与摘要可以被同时重写；因此这只证明导出文件内部一致，**不能**证明行情来源、因子公式或收益本身正确，也不是防篡改签名。若需要独立重算，仍须取得同一私有数据包。
