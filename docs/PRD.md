## 1 项目概述

本项目建设一个可在个人电脑私有部署的量化投资多因子研发平台。系统分为平台与产品两部分。平台负责用户权限、数据存储、任务调度、运行日志和结果归档；产品负责因子配置、因子计算、单因子检验、结果展示和研究报告生成。

首期以课程验收为目标，在2026年12月中旬前完成“数据导入、因子选择、异步计算、统计检验、图表展示、报告生成、实验复现”的闭环。系统不连接真实资金账户，也不提供投资建议。

## 2 项目目标

### 2.1 业务目标

1. 让研究人员在页面中选择内置因子、股票样本、时间范围和处理参数。
2. 将长耗时计算提交到后台执行，页面可以查看进度、日志和失败原因。
3. 统一生成IC、Rank IC、ICIR、分组收益、多空收益、换手率和相关性结果。
4. 保存数据版本、因子版本、参数和运行环境，使研究结果可以复现。
5. 自动生成结构化结果和可阅读的HTML研究报告，并支持打印或导出PDF。

### 2.2 课程验收目标

- 演示平台和产品之间的明确边界。
- 展示权限、数据、异步任务、因子研究和报告的完整流程。
- 使用固定样例数据稳定完成不超过10分钟的演示。
- 四位成员分别提交可以独立验收的责任包。

### 2.3 成功指标

| 指标 | 验收标准 |
| --- | --- |
| 核心流程 | 从登录到下载报告能够完整运行 |
| 计算性能 | 300只股票、3年日频、单因子完整检验不超过60秒 |
| 页面性能 | 普通查询在推荐环境中不超过2秒 |
| 结果正确性 | 黄金数据集的关键指标与独立验算结果在约定容差内一致 |
| 可复现性 | 任务能够追溯数据版本、因子版本、参数和代码版本 |
| 私域部署 | 固化数据后，核心流程可以在单台Windows电脑离线运行 |

## 3 用户和权限

### 3.1 用户角色

| 角色 | 权限 |
| --- | --- |
| 管理员 | 管理用户、数据集、数据版本和全部研究任务 |
| 研究员 | 查看授权数据，创建因子研究任务，查看和下载自己的结果 |
| 只读用户 | 查看已授权的结果和报告，不得发起或修改任务 |

首期由管理员预置账号，不实现自行注册、邮件验证、忘记密码、单点登录和复杂审批。

### 3.2 权限对象

权限作用于项目、数据集、因子、研究任务和报告。后端必须校验权限，不能只依赖前端隐藏按钮。

## 4 核心业务流程

1. 管理员导入CSV或Parquet数据，系统校验字段、日期、重复值和基本价格关系。
2. 管理员发布数据版本，研究员只能使用已发布版本。
3. 研究员从因子库选择因子版本，设置样本、日期范围和处理参数。
4. 系统创建研究实验和后台任务，Celery Worker执行数据读取、预处理、因子计算和检验。
5. 页面显示等待、运行、成功、失败或取消状态，并展示进度和日志摘要。
6. 任务成功后，系统保存指标、图表数据和报告。
7. 用户打开结果详情，核对数据版本、因子版本和参数，随后查看或下载报告。

## 5 功能需求

### 5.1 登录与用户管理

- 支持账号密码登录和退出。
- 使用安全哈希保存密码。
- 管理员可以创建、停用账号并配置角色。
- 未登录用户不能访问业务页面或接口。

### 5.2 数据集管理

- 管理员可以导入CSV和Parquet文件。
- 数据集记录名称、市场、频率、日期范围、股票数量、来源、创建人和校验和。
- 数据发布后形成不可变版本；更新数据时创建新版本。
- 提供字段预览、记录数统计、缺失值统计和异常检查结果。
- Tushare Token仅用于离线采集脚本，不发送到浏览器。

首期基础数据包括证券主表、交易日历、日行情、复权因子、每日指标、证券状态、行业历史和基准行情。

### 5.3 因子库

首期提供以下内置因子：20日动量、5日反转、20日波动率、20日换手率、市值和市盈率。

每个因子记录名称、类别、业务说明、计算公式、参数、创建人、版本号和创建时间。修改公式或参数定义必须创建新版本，历史任务继续绑定原版本。网页执行任意Python代码不属于首期范围。

### 5.4 研究任务

- 用户选择数据版本、股票样本、日期范围、因子版本和预处理参数。
- 支持去极值、标准化以及可选的市值和行业中性化。
- 任务状态包括待执行、运行中、成功、失败和已取消。
- 用户可以查看进度、失败原因和日志摘要，并手动重试失败任务。
- 任务成功后，输入参数和结果不可原地修改；重新运行会生成新实验。

### 5.5 单因子检验

系统计算覆盖率、IC、Rank IC、IC均值、IC标准差、ICIR、分组收益、多空收益、换手率和因子相关性。因子值在交易日收盘后形成，最早用于下一交易日收益检验。财务数据必须按实际披露日期生效。

系统保存未复权价格和复权因子，研究收益采用后复权口径。前复权价格仅用于界面展示。所有报告必须披露复权方式、样本构造和已知偏差。

### 5.6 结果与报告

- 结果页展示指标摘要、IC时间序列、IC分布、分组净值、多空净值、换手率和因子相关性。
- 结构化结果写入数据库或JSON文件，图表使用同一份结果数据生成。
- HTML报告包含因子定义、数据范围、预处理参数、指标、图表、运行信息和风险说明。
- 报告支持浏览、下载和打印为PDF。
- 报告不得使用“推荐买入”等投资建议措辞。

### 5.7 可选本地模型

本地模型属于P2加分项。系统可以通过兼容接口连接Ollama，根据已计算的结构化指标草拟报告摘要。模型不得计算核心指标；未安装、超时或失败时，系统使用固定模板完成报告。

## 6 页面需求

| 页面 | 主要内容 |
| --- | --- |
| 登录 | 账号、密码和错误提示 |
| 项目总览 | 数据集、因子、任务和近期结果摘要 |
| 数据集管理 | 导入、版本、校验结果和字段预览 |
| 因子库 | 因子列表、详情、参数和版本 |
| 新建研究任务 | 样本、日期、因子和预处理配置 |

| 用户管理 | 管理员维护账号及角色 |

## 7 数据设计

### 7.1 存储分工

- PostgreSQL保存用户、角色、数据目录、因子定义、任务、实验、指标摘要和报告索引。
- Redis保存队列消息、任务进度和短期缓存。
- Parquet保存行情、因子矩阵和大体积计算结果。
- DuckDB直接查询Parquet并向计算模块提供数据。

### 7.2 主要实体

用户、角色、项目、数据集、数据版本、因子、因子版本、研究实验、执行任务、指标结果、报告和审计事件构成主要实体。研究实验必须同时绑定数据版本和因子版本。

### 7.3 数据质量规则

- 证券代码、交易日期和市场不能为空。
- 同一证券同一交易日不得重复。
- 最高价不应低于开盘价、收盘价或最低价。
- 成交量和成交额不得为负数。
- 停牌缺失与采集缺失必须区分。
- 导入文件保存校验和，保证版本内容可验证。

## 8 系统架构

首期采用模块化单体和独立Worker。FastAPI内部按身份权限、数据、因子、研究、任务和报告划分模块，各模块通过公开接口协作。React前端只访问FastAPI，不直接连接数据库或存储文件。

Docker Compose统一启动Web、API、Worker、PostgreSQL和Redis。Mac用于设计和轻量开发，Windows配合WSL2和Docker Desktop承担主要开发、集成与答辩演示。

微服务不属于首期要求。未来可以优先拆分计算Worker、数据服务和报告服务，但拆分必须由独立扩容、独立发布或团队边界等真实需求触发。

## 9 非功能需求

### 9.1 可用性

- 关键表单提供默认值、字段说明和输入校验。
- 长任务不得阻塞页面请求。
- 错误信息说明失败阶段和可执行的处理方式。

### 9.2 安全

- 密码使用安全哈希，Token和密钥通过环境变量注入。
- 上传文件限制类型、大小和保存位置。
- 后端执行角色和资源权限检查。
- 日志不得记录密码、Token或完整敏感数据。

### 9.3 可维护性

- Python和前端依赖锁定版本。
- 核心模块拥有单元测试，数据流拥有集成测试，演示流程拥有端到端测试。
- 所有路径使用跨平台方式处理，不写死Windows盘符或Mac用户目录。

### 9.4 可复现性

报告和实验记录数据版本、因子版本、完整参数、代码版本、开始结束时间和运行状态。已成功的历史实验不得因因子或数据后续更新而改变。

## 10 优先级

| 优先级 | 范围 |
| --- | --- |
| P0 必须完成 | 登录权限、数据导入、数据版本、六个内置因子、异步任务、单因子检验、结果图表、HTML报告、复现信息、Docker部署 |
| P1 应当完成 | 历史指数成分、简单等权或IC加权多因子合成、任务取消、PDF导出 |
| P2 时间允许 | Ollama摘要、表达式因子编辑器、更丰富的监控图表 |

## 11 非目标

首期不实现实时行情、分钟或Tick数据、自动交易、券商接口、资金账户、复杂多因子优化、机器学习预测、网页任意Python执行、移动端、Kubernetes、多机容灾和生产级高并发。

## 12 测试与验收

### 12.1 测试层级

- 单元测试使用人工构造的5只股票、30个交易日数据覆盖缺失、停牌、极值和复权场景。
- 集成测试使用20至50只股票的固定Parquet快照。
- 研究正确性测试使用独立Excel或Python脚本生成黄金结果。
- 端到端测试覆盖登录、提交任务、查看结果和下载报告。

### 12.2 核心演示剧本

管理员查看数据版本，研究员选择20日动量因子和沪深300样本，提交异步任务，在任务中心查看进度，打开结果图表和研究报告，最后切换只读账号验证权限。全程控制在10分钟以内。

## 13 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 只有队长具备较强编程能力 | 集成工作集中、进度失衡 | 模块化开发，其他成员承担可独立验收的数据、研究和测试责任包 |
| 团队量化知识不足 | 指标口径错误 | 先完成共同学习和公式评审，使用黄金数据独立验算 |
| 第三方接口限流或网络失败 | 演示中断 | 提前固化Parquet快照，演示期间离线运行 |
| 当前成分股产生幸存者偏差 | 研究结论偏高 | 报告明确披露；历史成分作为P1功能 |
| 范围持续扩大 | 无法按时验收 | P0冻结，新增需求只能进入P1或P2 |
| 跨平台差异 | Windows和Mac行为不一致 | Docker Compose、WSL2、统一换行符和自动化测试 |
