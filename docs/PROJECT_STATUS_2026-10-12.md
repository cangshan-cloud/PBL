# 项目进度与后续计划（2026-10-12）

## 当前结论

课程演示所需的主要业务闭环已在 Mac 环境跑通：登录 → 使用已发布演示数据 → 提交研究任务 → 查看指标、图表和日志 → 下载 HTML 报告。OrbStack Compose 中的 API、Web、Worker、PostgreSQL、Redis 异步链路已有一次端到端验收记录。项目尚不能宣布“全部 PRD 已完成”或“Windows 私域部署已验收”。

## 已形成的成果

| 范围 | 当前成果 | 证据或限制 |
| --- | --- | --- |
| 平台 | 三种角色与资源权限；数据版本、质量检查、SHA-256；任务排队、取消、重试、日志和报告归档 | 后端自动测试；Mac 本地及 OrbStack 验收记录 |
| 研究产品 | 六个内置因子、等权多因子组合；IC、Rank IC、ICIR、分组与多空收益、成本后净值、换手率；规则化结论草稿 | 黄金样本验算；报告和任务详情可追溯参数、数据、因子与代码指纹 |
| 展示与交付 | React 工作台、结果图表、实验对比、HTML 报告、任务 JSON 复现包 | 前端生产构建；报告可在浏览器打印为 PDF，但尚无服务端 PDF 导出 |
| 部署与质量 | 同一份 Docker Compose 用于 Mac 与计划中的 Windows；GitHub Actions 配置 Linux/Windows 测试与构建 | Mac/OrbStack 已验证；Windows 实机与 GitHub Actions 云端结果仍需单独核实 |

本轮新增的任务复现包由任务中心下载，包含数据文件校验和、因子公式与版本、全部研究参数、代码指纹、任务状态、结构化结果及结果摘要校验和、报告校验和、任务日志。它不携带原始数据文件或报告文件，也不会验证它们当前仍存在；跨机器重新计算仍需取得同一数据版本和代码。

## 当前验证

- 后端：`make test`，69 项通过。
- 研究计算：`make golden`，固定手算样本通过。
- 前端：`npm run build --prefix frontend`，生产构建通过。
- Mac 端到端与 OrbStack 异步验收：见 `MAC_E2E_ACCEPTANCE.md`；性能单次测量见 `PERFORMANCE_ACCEPTANCE.md`。上述记录不替代 Windows 验收。

## 建议的短期顺序

1. 本周：确认导师第一次汇报日期、课程硬性评分项与四名成员信息；由 B/C/D 分别提交首版数据字典、独立验算和验收用例，队长整合。不要用代码提交数替代个人验收材料。
2. 下一开发迭代：补自动化 API/浏览器端到端测试，尤其是管理员导入发布、研究员研究、只读权限和复现包下载；核查 GitHub Actions 的实际运行结果。
3. 获得 Windows 环境后：优先完成离线 Compose 部署与完整演示，记录问题；再决定是否增加 Parquet/中性化等扩展项。
4. 第二次汇报前：固定一个可复现的真实或公开 A 股小样本及来源说明，由成员 C 对关键因子指标做独立验算。
5. 最终验收前：冻结范围，整理四人署名材料、演示脚本和已知限制，完整彩排控制在 10 分钟内。
