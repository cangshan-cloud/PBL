# 扩展项取舍建议（2026-10-12）

项目由队长自主控制进度，课程验收优先。以下是候选项，不代表已经决定开发；新增范围应先写明数据来源、验收证据和对既有演示稳定性的影响。

| 候选项 | 当前价值 | 主要前提与风险 | 建议 |
| --- | --- | --- | --- |
| 真实 A 股样本的 API/Worker 自动验收 | 高：证明核心链路不只适用于合成数据 | 原始数据不宜直接公开再分发；需本机样本及运行中 Compose | 已实现并通过，保持为演示前自检 |
| 历史股票池、停牌与可交易性口径 | 高：提高研究可信度 | 需要有日期的成分与状态数据、明确许可；否则会引入幸存者偏差 | 下一阶段优先做数据方案和人工验算，再决定实现 |
| 可靠的逐日总市值与财务披露时点 | 高：使真实样本覆盖市值因子，并降低 PE 前视风险 | 字段来源、单位、发布时间、历史修订均需核对 | 数据口径未确认前不补值、不声称六因子真实数据全覆盖 |
| Parquet 导入 | 中：利于更大数据集 | 导入、校验、版本与跨平台依赖都要增加；现有 25MB CSV 足够当前样本 | 暂缓，除非验收明确要求 |
| 行业／市值中性化 | 中：研究方法更完整 | 依赖同日可得行业与市值，需小样本手算验证；错误实现比不实现更危险 | 暂缓，先解决历史数据口径 |
| IC 加权或自定义权重多因子 | 中：展示更多组合方法 | 滚动权重必须只用过去信息；短样本极易过拟合 | 暂缓，等权组合已满足首期演示 |
| 服务端 PDF 导出 | 低：浏览器已可打印 HTML 报告为 PDF | 增加渲染依赖与跨平台字体问题 | 暂缓 |
| 本地模型摘要 | 低：加分展示，非核心指标 | 模型输出不可作为计算结果；需处理超时、幻觉与离线失败 | 最后考虑，不进入核心验收路径 |

下一次范围决策建议只回答两个问题：一是是否能取得有明确使用权、历史时点可靠的数据；二是课程评分是否要求某个尚未实现的技术点。若答案都是否，优先完成独立指标验算、GitHub Actions 核对、演示彩排和四名成员验收材料，不再扩张功能。
