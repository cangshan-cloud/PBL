# CHG-20261121-001 四人 PBL 独立作业包

## 变更概述

依据教师提供的 PBL1/PBL2 四种 `.doc` 模板和 2026-11-20 的 M1—M4 功能模块分工，为 A/B/C/D 四名成员分别生成四份独立 Word 作业，共 16 份。每份作业替换了模板中的蓝字任务说明，保留评分表，并追加与个人模块对应的完整答案、图表和验收内容。

同时修正功能模块分工表中 M1、M2 两处不存在或过于笼统的代码路径，使后续报告可以准确定位当前仓库实现。

## 决策过程

1. 题目不能按旧的“架构/数据/研究/测试”岗位名称拆分，必须对应最新 M1—M4 功能模块，便于四人后续分别编写模块章节。
2. PBL1 作业1严格采用 2 页答案正文并附模型图；PBL1 作业2采用 2 页答案正文，包含组件架构、伪代码和数据/接口模型。
3. 原模板没有限定 PBL2 的最终交付格式，因此将 PBL2 作业1定义为“产品方案与验收用例”，将 PBL2 作业2定义为“软件组件转化与验证”，形成从业务到组件的递进关系。
4. 团队基础信息未知，不推测姓名、学号、班级和任课教师，统一使用明显占位符。
5. 为保持原始模板可追溯，先把 `.doc` 转换为 `.docx`，再由可重复运行的脚本填充；不直接覆盖用户提供的原文件。
6. 文档执行事实按项目既有规则记录为 Codex 代生成和核验，不写成四名成员本人已完成操作；按用户约定不再要求成员签收。

- 成品结构检查：`tools/check_pbl_assignment_docs.py`

- 四人个人材料链接：`docs/member-deliverables/A_系统架构与集成验收.md`、`B_数据工程与质量验收.md`、`C_因子研究与指标验证.md`、`D_产品测试与展示验收.md`

## 验证结果

- 生成数量：16/16；每名成员 4 份，PBL1/PBL2 各两份。
- 内容核对：每份含个人模块题目、封面占位符、模板评分表和答案正文；PBL1 作业1含模型图，PBL1 作业2含架构图、伪代码及数据/接口模型；PBL2 两份分别含产品验收或组件验证内容。
- 版式核对：使用文档渲染工具逐份转为页面图片；清除模板末尾分页符与答案分节叠加造成的空白页，并收紧自生成表格边距，未发现截断、空白答案页或孤立表格残片。
- 页数口径：PBL1 作业1答案 2 页；PBL1 作业2答案 2 页；PBL2 作业1答案 2—3 页；PBL2 作业2答案 2 页。总页数包含模板封面、任务说明和评分页，不等同于答案页数。
- 自动检查：DOCX ZIP 结构、占位符、标题、图形数量和 16 份唯一输出均在提交前复核；项目变更索引与文档链接检查同步执行。

## 未决事项与限制

- 队长需在提交前填写四人的真实姓名、学号、班级和任课教师，并确认学校是否要求特定文件名。
- `.docx` 在不同 Word/WPS 版本可能发生少量字体回退或行距变化，最终上传前应在实际提交软件中快速逐页查看。
- 本批材料不新增成员亲自操作证据，也不改变四人各 25% 的课程贡献口径。
