- 日期：2026-10-14
- 类型：tool + delivery
- 状态：implemented / verified，原有 OrbStack 宿主机端口待排查
- 关联提交：与本记录同次提交

## 背景与目标

原有 `verify_compose_stack.py` 会创建任务，适合链路烟测，不适合答辩前反复核查账号和演示资源。成员 D 尚需可复做的十分钟剧本与彩排记录模板。本次增加不创建研究记录的预检及演示材料，并如实记录现场可达性问题。

## 决策过程

将“只读预检”和“写入任务的完整烟测”分开：前者检查账号、已发布合成数据、因子目录和只读页面所需列表；后者仅在需要验证 Worker/报告且允许留下验收记录时运行。历史私有包设为可选门槛，不让主演示依赖本机私有数据。答辩前检查宿主机端口，而不是仅依据 Docker 的 `healthy`。成员 D 的彩排证据仍须本人生成，模板不计作其已完成工作。

## 验证与结果

- 定向测试 3 项通过；`make test` 全量 114 项通过。
- 在独立 8002 端口、临时 SQLite API 上运行预检，四项基础检查全部 PASS；开启 `--require-historical` 时因该隔离环境没有发布历史包而按预期 FAIL。临时测试数据库和运行目录已清理。
- 对原有 `fbl` 栈只读检查：`docker compose ps` 显示服务健康，`docker inspect` 有 `127.0.0.1:8000` 映射，容器内 `/health` 返回 200；宿主机 `curl` 访问 `127.0.0.1:8000` 和 `localhost:8000` 均连接拒绝，因此原有栈**未通过演示就绪预检**。未重启或修改该栈。
