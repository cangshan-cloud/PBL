# CHG-20261019-017 适配导入浏览器验收与更换文件保护

## 问题与决策

CHG-013 至 CHG-016 已有接口/前端测试，但缺少实际页面文件上传验收。隔离浏览器测试中，正常预览与导入可用；同时发现预览后更换文件会清除预览，却可能沿“未预览直接导入”路径继续，绕开本应生效的预览—导入绑定。决定保留首次未预览的直接导入能力，但只要用户已尝试预览，之后更换文件就必须重新预览才能按适配模式导入。标准 CSV 导入不受影响。服务端原有 `expected_source_sha256` 冲突校验仍是最终防线。

## 修改位置

- `frontend/src/main.tsx::previewAdapter`、文件输入 `onChange`、`uploadDataset`：记录本次表单是否已尝试预览、是否在其后换过文件；成功重新预览才清除失效状态，导入成功或退出登录后重置状态。
- `frontend/src/adapter-upload.ts::prepareAdapterImportBody`：已换文件的适配导入抛出“请重新预览”错误，不发送请求；标准导入和首次未预览直接适配仍保持原行为。
- `frontend/tests/adapter-upload.test.ts`：新增换文件后适配导入被阻止、标准导入不受影响的回归。
- `docs/CN_DATA_ADAPTER.md`、`docs/CHANGE_INDEX.md`、A/B/C/D 四责任包：补齐操作契约、代码位置与实测边界。实际执行者：Codex。

## 隔离浏览器验收

Mac 本机临时 SQLite、独立数据目录、API `127.0.0.1:18012`、Vite `127.0.0.1:15185`，管理员演示账户，上传的是三行合成 CSV，不涉及私有行情。实际完成：

1. 页面预览显示标准化后的 3 行、原文件 SHA-256 `75100e7c…7120a`，以及“1 个周末日期、2 行行情”的导入前警告。
2. `weekend_browser_qa` 导入后为 3 行、2 只证券；页面顶部同样显示 1 个周末日期、2 行行情，数据版本 SHA-256 `be84a84f…469df`（标准化 CSV，故不同于原文件指纹）。版本 `20261019.130756.588199` 随后在页面显示“已发布”。
3. 再次预览后切换到改价的 `weekend_adapter_changed.csv`，旧预览清除；点击适配导入出现“文件已更换，请重新预览后再适配导入”，数据版本列表未新增 `changed_guard_qa`。重新预览后显示新原文件 SHA-256 `7929852e…8d58b` 与末行价格 13。
