# CHG-20261026-006 成功任务定位同 Run 报告

## 问题与决策

上一轮建立了报告到任务的定位，但从任务详情查看参数和指标后仍需手动去报告中心搜索。决定只为成功任务提供“查看同 Run 报告”：将当前完整 Run ID 写入报告选择与检索后切换页面，沿用报告列表的权限和零匹配保护。待执行、失败和取消任务不显示该入口；不假设每个成功任务的报告都已立即可见，不修改 API、归档或研究计算。实际执行者：Codex。

## 修改内容与对应位置

- `frontend/src/main.tsx::openSelectedTaskReport` 与任务详情动作区：成功状态才导航，传递完整 Run ID 并触发报告列表加载；报告中心既有可见集合与选择规则防止回退到其他报告。
- `frontend/tests/report-list.test.ts`：同名报告按完整 Run ID 只选对应项；目标缺失时返回未选中，不落到其他归档。
- `docs/TASK_REPORT_LINK_BROWSER_QA_2026-10-26.md`、总索引及 A/B/C/D 四责任包：记录两条旧任务正例和未测边界。

## 验证结果与边界

前端 69 项测试及生产构建通过。隔离浏览器预设旧报告检索为 0/6，随后两条不同成功任务均跳转到各自完整 Run 的 1/6 份报告，iframe 与下载入口存在，控制台错误/警告 0。缺失归档的前端纯函数边界有自动化测试，但未造浏览器反例；不声称已验证异步归档时序。后端全量回归、金样本、台账和链接检查见本轮提交。用户修改的 Excel 和私有数据未入库。
