# CHG-20261120-001 四人分工改为功能模块

## 背景与目标

原 A/B/C/D 分工以“系统架构、数据工程、因子研究、产品测试”等职责描述为主，不利于把中期报告、末期报告和个人验收材料直接拆成四个功能章节。根据队长 2026-11-20 的要求，分工调整为 M1 平台基础与任务运行、M2 数据集管理与质量控制、M3 因子计算与研究检验、M4 研究工作台与报告交付。

## 决策过程

考虑过按技术层（前端、后端、数据、测试）拆分，但单个研究功能会被拆到多个人，后续报告仍难独立成章；也考虑沿用原岗位式责任包，仅补充任务清单，但无法解决职责名称与产品功能不对应的问题。最终选择按四个业务/平台功能模块划分，并用接口表定义跨模块协作。这样既与现有代码和证据对应，也便于把四份个人材料直接合入团队报告。

四人课程责任占比继续统一为 25%，不要求编码量相等。A 仍负责代码仓库、跨模块集成和发布。开发与测试可由 Codex 代执行，必须保留实际执行者，不把证据改写成成员本人完成。

## 修改内容与对应位置

- `docs/TEAM_MODULE_DIVISION_2026-11-20.md`：新增模块总表、代码边界、接口、报告章节映射和最低验收闭环。
- `docs/TEAM_PLAN.md`：将四人责任包更新为 M1—M4 功能模块。
- `docs/FIRST_MENTOR_REPORT.md`：更新团队分工表并修正旧的个人签收口径。
- `docs/member-deliverables/A_系统架构与集成验收.md`：改为 M1 模块标题和交付清单。
- `docs/member-deliverables/B_数据工程与质量验收.md`：改为 M2 模块标题和交付清单。
- `docs/member-deliverables/C_因子研究与指标验证.md`：改为 M3 模块标题和交付清单。
- `docs/member-deliverables/D_产品测试与展示验收.md`：改为 M4 模块标题和交付清单。
- `docs/CHANGE_INDEX.md`：登记本次决定与修改索引。

## 兼容与影响

为避免破坏大量既有链接，四份成员验收材料的文件名暂不改动，只更新标题并写明新模块名。历史变更记录仍保留原责任包称谓，不追溯改写。本次仅调整责任归属和文档结构，不改变应用代码、数据库、接口、研究公式或已有测试结论。

## 验证与结果

- 四个模块均有明确的功能、代码位置、输入输出、文档产物和最低验收闭环。
- 四份成员材料均链接到统一分工文档。
- 团队计划和第一次汇报使用相同的 M1—M4 名称。
- 执行 `python3 tools/check_change_ledger.py`、`python3 tools/check_document_links.py` 和 `git diff --check`；最终结果以提交前复核为准。

## 风险、回退与未决事项

成员姓名、学号和导师要求的最终报告格式仍待队长后续补充。若导师要求按传统岗位分工，可保留 M1—M4 内容，仅在报告展示层增加岗位别名，无需调整代码或历史证据。回退本次文档即可恢复旧表，不影响应用运行。
