## 浏览器证据与发现

使用 Playwright CLI 在本机 `localhost:5173`、隔离 SQLite 测试库和真实私有封存包完成管理员登录、包注册、清单预览、发布、历史任务执行、审计展示及报告中心预览。包 576 文件、242 成员日、95,776 行价格记录；任务共同有效观察 72,366 条，四因子审计表与报告均可见。首次从 `127.0.0.1:5173` 访问因默认 CORS 仅允许 `localhost:5173` 而无法登录；改用项目配置的 `localhost` 后通过。浏览器控制台只有缺失 favicon 的 404，未见应用逻辑错误。快照和截图保留在 Git 忽略的 `data/real/browser_evidence_20261014*`。

发现三处口径错误：历史包卡片沿用 CSV 字段质量标签，历史包预览的 `item/value` 被误显示为“100% 字段完整率”；旧单 CSV 模式下拉框仍列出历史包；历史报告通用结论建议“替换为真实 A 股历史数据”，与本次真实历史包矛盾。

## 修改内容与位置

- `frontend/src/main.tsx` 数据集页面：历史包改为“已校验文件/历史成员日/整包摘要”，清单预览隐藏 CSV 字段完整率；注册表单前移到数据版本列表之前，页面说明同时覆盖 CSV 与封存包。
- `frontend/src/main.tsx` 研究工作台：旧单因子与旧等权模式使用 `eligibleDatasets`，不再提供历史包选项；历史模式继续仅接受历史包。
- `backend/app/services/conclusions.py::build_run_conclusion`：历史模式的限制与下一步建议改为核对成分生效、来源授权、复权和停牌口径，不再说替换真实数据。
- `backend/app/services/reports.py::build_report_html`：历史包源价格明确标识 BaoStock `adjustflag=1`。
- `backend/tests/test_historical_task.py`：回归检查新报告与结论文案。
- `docs/HS300_BUNDLE.md`：更新浏览器验收结果及边界。

## 决策过程

三个问题均来自真实页面和报告内容，而非凭空增设功能。保留旧 CSV 的字段质量展示，但通过数据集类型分流；历史包只声明文件完整性，不冒充逐列行情质量。研究模式继续严格隔离，避免用户在旧任务中选错包。报告结论根据 `mode=historical_hs300_2024` 改写，既承认已使用真实历史样本，也保留成分时点、可交易性和成本假设限制。
