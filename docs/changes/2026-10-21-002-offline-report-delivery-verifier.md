# CHG-20261021-002 报告交付文件离线一致性核对

## 问题与决策

报告中心已经提供原归档和派生披露版，但下载后缺少不依赖运行中 API 的交叉核对办法。决定新增只读 CLI，要求用户分别保存数据版本和报告索引摘要作为独立参照，再检查原归档 SHA、数据身份、披露风险和派生文件只插入一段的字节边界。工具不调用网络、不访问数据库、不修改输入。优先使用现有 HTML 格式，不引入新接口或数据库表。实际执行者：Codex。

## 修改内容与位置

- `tools/verify_report_delivery.py`：四文件离线核对；严格校验摘要与质量字段格式；还原披露版首个 `<main>` 后的插入段，要求其余文本与原归档一致；风险段落与数据版本质量报告逐项比较；命令失败返回非零。
- `backend/tests/test_report_delivery_verifier.py`：用当前服务实际生成的披露版作为正例，覆盖正文、日期、报告摘要与数据 SHA 篡改反例，并覆盖无异常时的通用风险说明。
- `docs/REPORT_DELIVERY_VERIFICATION.md`：输入取得方法、命令及一致性/真实性边界。
- `docs/DEVELOPMENT_PLAN_2026-10-21.md`：P1 标记完成，P2 为下一轮；总索引与四责任包同步记录。

## 验证与限制

Mac 定向离线校验测试 **2 passed**；后端全量 **241 passed**（另有一条第三方弃用警告），前端 **43 passed** 且生产构建通过。工具本身纯只读且不改变运行时代码，故不重建 OrbStack 服务。它不能证明四个输入本身的来源真实性，也不验证股票行情或因子算法；若四个文件同时被协调篡改，一致性检查可能仍通过。
