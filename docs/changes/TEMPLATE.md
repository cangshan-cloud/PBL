# CHG-YYYYMMDD-NNN：简短标题

- 日期：YYYY-MM-DD
- 类型：feature / fix / refactor / docs / governance / decision-only
- 状态：open / accepted / implemented / verified / superseded
- 关联提交或议题：待提交时可写“与本记录同次提交”；提交后可补哈希。

## 背景与目标

说明触发原因、用户要求和本次范围；将事实与假设分开。

## 决策过程

记录考虑过的方案、关键取舍、最终选择及理由。用户尚未回答的问题列入“未决事项”，不得替用户选择。被后续决策替代时，在本记录和新记录中互相链接。

## 修改内容与对应位置

| 内容 | 位置（仓库相对路径 + 函数／章节，必要时行号） | 影响 |
| --- | --- | --- |
| 示例 | `backend/app/services/example.py::function_name` | 简述行为变化 |

纯文档记录写明“无代码改动”，同时列出被修改的文档位置。不要只写目录或宽泛模块名。

## 验证与结果

列出实际执行的命令、测试结果及未执行的验证；不要把计划写成已通过。

## 风险、回退与未决事项

写明已知限制、可恢复方式、需要用户决定的问题或“无”。
