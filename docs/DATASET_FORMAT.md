# 数据集导入格式

## 当前支持范围

当前版本支持UTF-8编码的CSV日行情文件。上传成功后先生成不可变的草稿版本，管理员确认质量报告后再发布。研究任务只能引用已发布版本。

非标准的 Tushare、BaoStock 或中文字段 CSV 可在导入前使用 A 股数据适配器，见 [CN_DATA_ADAPTER.md](CN_DATA_ADAPTER.md)。

单个文件默认不超过25MB，可通过环境变量`MAX_UPLOAD_BYTES`调整。

## 必填字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `trade_date` | `YYYY-MM-DD` | 交易日期 |
| `symbol` | 字符串 | 证券代码，建议使用`000001.SZ`格式 |
| `close` | 正数 | 导入价格，可为未复权或已复权价格；整个数据集须保持同一口径 |

## 可选数值字段

`open`、`high`、`low`、`volume`、`amount`、`adj_factor`、`turnover_rate`、`total_mv`、`pe`。

## 当前质量规则

- 必填字段不得缺失；
- 同一证券同一交易日不得重复；
- 收盘价必须大于0；
- 成交量、成交额、换手率和总市值不得为负数；
- 最高价不得低于开盘价、收盘价或最低价；
- 最低价不得高于开盘价或收盘价；
- 交易日期必须严格采用 `YYYY-MM-DD`，且为有效日历日期；`YYYYMMDD` 和 ISO 周日期不作为标准 CSV 日期接收；
- 文件必须使用UTF-8或UTF-8 BOM编码。
- 单行数值和质量报告中的数值均必须有限；拒绝 NaN、正负无穷、单行浮点溢出，以及数值汇总均值溢出；
- 表头不得重复，数据行列数必须与表头一致；
- 提供数值复权因子时必须大于零。任务默认直接使用 `close`；也可明确选择 `close × adj_factor`，这时所选证券的每一行都须提供有效因子。

质量报告同时记录每个字段的缺失数量和完整率，以及数值字段的有效数量、最小值、最大值和均值。可选字段允许为空，但对应因子只会使用非空且历史长度足够的观测。

极端输入即使每一行都能解析为有限浮点数，汇总求和仍可能溢出；此时导入在生成质量报告前失败，不保存包含 `Infinity` 的元数据。需要保留此类异常记录时，先在原始来源中核对并清洗，不能依赖导入器自动截断。

数据集页面可以查看前20行预览。预览接口会读取文件一次，用同一份字节核对 SHA-256 并解析展示；文件被外部修改后返回冲突错误，不展示已经失去版本完整性的内容。研究任务读取 CSV 时同样从已核对的字节快照解析，避免校验后再次打开文件造成内容变化窗口。单元格预览最多展示200个字符，接口最多返回100行。

## 最小示例

```csv
trade_date,symbol,open,high,low,close,volume
2025-01-02,000001.SZ,10.00,11.00,9.00,10.50,1000
2025-01-03,000001.SZ,10.50,11.20,10.00,11.00,1200
```

## API流程

1. 可选调用 `POST /api/v1/datasets/adapt/preview` 预览常见 A 股 CSV 的字段转换。
2. `POST /api/v1/datasets/import`，使用multipart表单上传`dataset_key`、`name`和`file`；需要自动适配时增加 `normalize_cn_csv=true`。
3. `GET /api/v1/datasets/{id}`查看质量报告和SHA-256校验和。
4. `POST /api/v1/datasets/{id}/publish`发布版本；发布前重新校验磁盘文件的 SHA-256，文件丢失返回 410、内容变化返回 409，失败时版本保持草稿状态。重复发布也会重新校验。
5. `GET /api/v1/datasets/{id}/preview?limit=20`查看字段和数据样例。
6. `GET /api/v1/datasets`查询全部版本。

原始文件名只作为审计信息保存；实际存储路径和文件名由服务端生成，不能由上传者控制。

导入时先写入新版本文件，再提交数据库记录。如果磁盘写入或数据库提交失败，服务端会回滚会话并清理本次新建的文件与版本目录，不会删除已有版本。磁盘与数据库不是同一个原子事务；异常断电等进程外故障仍可能留下需人工核查的孤儿文件。

## 存储巡检

在项目根目录执行 `make audit-data`，或在 Compose 启动后执行 `docker compose exec api python -m app.services.storage_audit`。本机命令需使用与 API 相同的 `DATABASE_URL` 和 `DATA_ROOT`；若默认 SQLite 文件不存在，命令会报错而不会新建数据库。巡检检查所有数据版本的文件是否丢失、SHA-256 是否变化，并找出 `DATA_ROOT/<数据集>/<版本>/*.csv` 下未被数据库引用的文件；仓库自带的演示数据虽然位于 `DATA_ROOT` 外，仍会核对其文件和校验和。

结果以 JSON 输出；无问题时退出码为 0，有问题为 1，本地 SQLite 数据库文件不存在时为 2。命令只报告问题，不自动删除、覆盖或修复文件。若发现未引用文件，先核对数据库备份和采集记录，再决定如何处理。
