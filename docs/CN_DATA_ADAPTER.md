# A股 CSV 数据适配器

## 1. 使用场景

数据适配器用于把常见行情工具导出的离线 CSV 转换为 FactorLab 标准字段。它不联网、不抓取数据，也不绕过数据供应商授权；团队仍需自行确认数据来源、许可范围和研究用途。

当前支持：

- Tushare 常见字段，如 `ts_code`、`trade_date`、`vol`、`total_mv`；
- BaoStock 常见字段，如 `date`、`code`、`turn`、`peTTM`；
- 常见中文字段，如“日期”“股票代码”“开盘”“最高”“最低”“收盘”“成交量”“成交额”“换手率”“总市值”“市盈率”；
- UTF-8、UTF-8 BOM 和 GB18030 编码。

## 2. 标准化规则

- 日期统一为 `YYYY-MM-DD`，可识别 `YYYYMMDD`、`YYYY/MM/DD` 和 `YYYY.MM.DD`；
- `sh.600000`、`600000SH` 等代码统一为 `600000.SH`；
- 无市场后缀时，5、6、9 开头推断为上交所，0、1、2、3 开头推断为深交所，4、8、92 开头推断为北交所；
- 未识别字段不会进入标准文件，但会列入 `dropped_columns`；
- 两个源字段映射到同一标准字段时拒绝转换，避免静默覆盖；
- 转换完成后必须通过平台原有数据质量校验，才能导入草稿版本。

代码市场推断只适合常见六位股票代码。基金、债券、指数和特殊历史代码应在源文件中明确提供市场后缀，不能依赖自动推断。

## 3. 不自动转换的单位

适配器不会猜测或缩放以下单位：

- 成交量可能使用“股”或“手”；
- 成交额可能使用元、千元或万元；
- 换手率可能表示百分数 `1.2`，也可能表示小数 `0.012`；
- 总市值可能使用元、万元或其他供应商口径。

这些字段会原样保留，适配报告同时给出警告。管理员必须根据数据源文档确认单位，并保证不同数据版本口径一致。

## 4. 页面与接口

管理员在“数据集”页面选择 CSV 后，可以先点击“适配预览”，检查字段映射和转换结果。确认后勾选“自动适配常见A股字段”，再执行导入。

```http
POST /api/v1/datasets/adapt/preview
```

上传 `file`，返回映射报告、原文件 `source_sha256` 及前 10 行标准化预览，不保存文件。

适配器 1.2.0 的预览报告还返回 `validation.weekend_date_count` 与 `validation.weekend_row_count`。若非零，页面警告管理员导入前核对源文件日期；适配器不自动删行或改写日期。导入后的数据版本质量报告保留相同计数。该诊断只识别周六、周日，不等于交易所日历或节假日校验。

适配器 1.3.0 另按[已封存的 2024–2026 沪深交易所公告休市规则](MARKET_CALENDAR_SCOPE.md)提示休市工作日行情和未覆盖年份。预览 `validation` 返回规则版本、全部命中日期、命中日期数与行数、未覆盖年份；页面在导入前显示具体日期及规则版本。导入后的质量报告也保存规则版本、日期及行数。此规则不是完整交易日认证；旧已发布版本不会自动补算。

适配器 1.3.1 将“确认成交量单位”提醒限定为实际映射了成交量字段的文件；只有日期、代码和收盘价的文件不会收到无关提醒。标准化内容及休市诊断口径不变。浏览器只预览证据见 [CHG-20261020-008](changes/2026-10-20-008-calendar-preview-browser-qa-and-volume-warning.md)。

```http
POST /api/v1/datasets/import
```

除原有 `dataset_key`、`name` 和 `file` 外，传入表单字段 `normalize_cn_csv=true`。页面在完成预览后还会传入可选的 `expected_source_sha256`：它必须是 64 位小写十六进制 SHA-256，且只在启用适配时有效；服务端对本次上传的原始字节重新计算摘要，不一致则返回 409 且不创建草稿，管理员应重新预览。未预览时仍可按原方式直接适配导入。接口先转换，再创建不可变草稿版本；完整适配报告保存在数据版本的 `quality_report.adapter_report` 中。数据版本自己的 `checksum` 是标准化后 CSV 的摘要，通常不同于预览原文件的 `source_sha256`。

页面若在预览后更换所选文件，会清除旧预览，并在再次适配导入前要求重新预览；这防止页面把“已换文件”误当作从未预览的直接导入。直接调用 API 而不传预期摘要仍保留兼容行为。

已发布版本若含周末行，数据集页和研究工作台选中该版本时都会展示版本身份、周末日期数与行情行数。研究工作台的提醒随所选版本切换；它是人工复核提示，不证明交易所日历，也不自动阻止研究或删改原数据。

两个接口都仅允许管理员调用，并沿用上传大小限制。

## 5. 复权状态与输入完整性

适配器 1.1.0 将 BaoStock 的 `adjustflag`（1后复权、2前复权、3不复权）保存到来源元数据 `source_adjustment_flags`，不再将它映射为数值复权因子 `adj_factor`。混合状态或未知状态会被拒绝。字段定义参考 [BaoStock API文档](https://github.com/zxygithub/baostock/blob/master/docs/pythonAPI.md)。

研究任务默认直接使用导入的 `close`。若导入的是未复权价格，且 CSV 中另有数值乘数 `adj_factor`，可在任务中明确选择 `close × adj_factor`。BaoStock 的 `adjustflag` 只是价格状态标记，不是数值乘数；已复权的 BaoStock 价格不能再次选择因子调整。管理员仍须确认数据集内所有价格采用一致口径。

从 2026-10-22 起，新生成的研究报告若绑定的版本含单一有效 `source_adjustment_flags`，会在“数据质量与来源限制”中披露该来源状态，并说明任务默认直接使用导入的 `close`、未把状态码当作数值乘数；动态交付披露副本也重复该提示。此披露只是原数据源声明的口径，不验证其实际复权计算；旧归档报告保持原字节，不追溯重写。

单因子和多因子任务若请求 `close × adj_factor`，已适配来源标记为 `1` 或 `2` 时会在创建任务前返回 400，不留下必然失败的排队任务；执行阶段仍会复核。标记 `3` 只表示来源声明未复权，不免除数值 `adj_factor` 逐行完整性检查。

标准导入和适配导入都会拒绝重复表头、行列数量错位及无限大数值。标准导入还会拒绝 `NaN`；适配器把明确的缺失占位符 `NaN` 转为空值，随后按必填/可选字段质量规则处理。数值复权因子必须大于零。
