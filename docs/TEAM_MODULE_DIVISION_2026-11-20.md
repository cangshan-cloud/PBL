# 四人功能模块分工（2026-11-20 版）

## 1. 分工原则

本版将原先偏岗位性质的“架构、数据、研究、测试”责任包，改为四个可以独立编写设计、实现、测试和验收章节的产品功能模块。四名成员的课程贡献占比均为 25%，但实际编码量允许不同；队长继续负责仓库、技术主线和最终集成。开发与测试可由 Codex 代执行，材料必须记录实际执行者，不把代执行写成成员亲测。

## 3. 模块边界与协作接口

| 上游模块 | 交付给下游的内容 | 下游模块 | 联调验收点 |
| --- | --- | --- | --- |
| M2 数据集管理与质量控制 | 已发布的数据版本、字段定义、质量摘要和可用证券日期 | M3 因子计算与研究检验 | 同一数据版本可重复读取；缺字段、非法值和覆盖不足时明确失败或披露 |
| M3 因子计算与研究检验 | Run 参数、逐日指标、汇总指标、诊断和复现信息 | M4 研究工作台与报告交付 | 页面、CSV、JSON 与 HTML 报告对同一 Run 的值和日期一致 |
| M1 平台基础与任务运行 | 身份权限、API、Run 状态、日志、持久化和文件授权 | M2/M3/M4 | 研究员可运行、查看者只读、越权被拒；任务失败可追踪，重启后记录保留 |
| M4 研究工作台与报告交付 | 用户参数与展示需求、浏览器验收结果 | M1/M2/M3 | 参数完整传入；错误信息可理解；已保存结果不被前端重新解释或静默补值 |

跨模块缺陷由发现模块记录，归属到造成问题的模块修复，A 负责合并、回归和发布；这不改变四个模块各 25% 的课程责任口径。

## 4. 后续报告的统一章节映射

后续中期报告、末期报告、答辩 PPT 和四份独立验收材料统一使用以下章节名：

1. M1 平台基础与任务运行模块；
2. M2 数据集管理与质量控制模块；
3. M3 因子计算与研究检验模块；
4. M4 研究工作台与报告交付模块。

每章固定写六项：模块目标、功能清单、设计与代码位置、输入输出、测试证据、限制与后续计划。历史材料中的旧责任包名称仍可保留作为历史称谓，但新文档应优先使用 M1—M4 名称。

## 5. 独立验收最低要求

| 模块 | 最低可验收闭环 |
| --- | --- |
| M1 | 不同角色登录 → 研究任务进入队列 → Worker 完成 → 状态、日志和报告持久化 → 服务重启后仍可查询 |
| M2 | 选定数据版本 → 核对字段和摘要 → 执行质量规则 → 展示异常/限制 → 研究任务绑定该版本 |
| M3 | 选定因子与参数 → 完成预处理和指标计算 → 与黄金样例或独立工具核对 → 披露统计与投资局限 |
| M4 | 工作台提交 → 任务中心查看 → 图表和逐日值核对 → 报告预览 → CSV/JSON/HTML 下载并确认同一 Run |

验收结论必须区分“自动测试通过”“Codex 代执行浏览器验收”“队长本人产品实测”和“成员本人说明/操作”，不得互相替代。
