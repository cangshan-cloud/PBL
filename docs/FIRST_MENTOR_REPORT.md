## 一、项目背景

量化研究通常需要反复处理行情数据、编写因子、运行统计检验、绘制图表并整理研究报告。如果数据口径、因子公式和运行参数分散在不同脚本中，研究结果容易出现无法复现、难以比较和过程缺少记录等问题。

本项目拟建设一个面向少量研究人员的“量化投资多因子研发平台”。系统在结构上分为平台与产品两部分：

- **平台部分**负责身份权限、数据版本、任务调度、运行日志、结果存储和私有化部署，解决研究活动中的共性问题。
- **产品部分**负责因子定义、因子计算、单因子检验、结果图表和研究报告，直接面向研究人员产出研究结果。

项目以课程验收为主要目标，仅研究沪深 A 股日频数据，不连接真实资金账户，不执行自动交易，也不向用户提供投资建议。

## 二、项目目标

### 2.1 总体目标

在2026年12月中旬前完成一个能够在个人电脑私有部署的因子研究系统，使研究人员可以从页面选择数据、因子和参数，提交后台任务，查看检验结果并生成研究报告。

### 2.2 首期目标

首期必须完成以下闭环：

```text
数据导入与版本发布
        ↓
选择因子和研究参数
        ↓
提交后台研究任务
        ↓
计算因子与检验指标
        ↓
展示图表和复现信息
        ↓
生成因子研究报告
```

### 2.3 验收指标

| 验收项 | 目标 |
| --- | --- |
| 核心流程 | 从登录、创建任务到查看报告可以完整运行 |
| 研究范围 | 沪深 A 股、日频、固定样例数据 |
| 因子范围 | 首期完成6个内置因子 |
| 计算性能 | 300只股票、3年日频、单因子检验不超过60秒 |
| 页面性能 | 普通查询在推荐环境下不超过2秒 |
| 可复现性 | 保存数据版本、因子版本、参数、代码版本和运行时间 |
| 部署方式 | Windows + WSL2 + Docker Desktop，可在固定数据下离线运行 |
| 演示时长 | 完整演示控制在10分钟以内 |

## 三、需求范围

### 3.1 首期必须完成的功能

1. 管理员、研究员和只读用户三类角色。
2. CSV或Parquet数据导入、质量检查和不可变数据版本。
3. 六个内置因子：20日动量、5日反转、20日波动率、20日换手率、市值和市盈率。
4. 去极值、标准化以及可选的市值和行业中性化。
5. 后台异步任务、进度查询、日志摘要和失败原因。
6. IC、Rank IC、ICIR、分组收益、多空收益、换手率和相关性。
7. 指标摘要、IC序列、分组收益和多空净值等结果展示。
8. HTML研究报告和完整复现信息。
9. Docker Compose私有化部署。

### 3.2 首期不做的内容

- 实时行情、分钟或Tick数据；
- 券商接口、实盘交易和资金账户；
- 机器学习预测、复杂组合优化和强化学习；
- 网页执行任意Python代码；
- 移动端、Kubernetes、生产级高并发和多机容灾；
- 将本地大模型作为指标计算工具。

以上内容如有余量，只能进入后续优先级，不占用首期核心闭环时间。

## 四、目标用户与典型流程

### 4.1 目标用户

系统仅服务少量研究人员和课程评审人员。

| 角色 | 主要权限 |
| --- | --- |
| 管理员 | 管理用户、数据集、数据版本和全部研究任务 |
| 研究员 | 创建研究任务，查看和下载自己的结果 |
| 只读用户 | 查看授权结果与报告，不得创建或修改任务 |

### 4.2 典型研究流程

1. 管理员导入并发布一份数据版本。
2. 研究员选择数据版本、股票样本、日期、因子和处理参数。
3. 系统创建实验记录，并把计算任务提交给后台 Worker。
4. Worker读取数据，完成因子计算、预处理和指标检验。
5. 系统保存指标、图表数据、日志和报告。
6. 研究员查看结果，并确认数据版本、因子版本和完整参数。
7. 只读用户查看已授权的研究报告，验证角色权限。

## 五、开源项目调研

项目组对现有量化与实验追踪项目进行了初步调研，结论如下。

| 参考项目 | 可借鉴内容 | 本项目取舍 |
| --- | --- | --- |
| Microsoft Qlib | 数据、信号、工作流、实验记录和分析分层 | 作为主要架构参考，不直接引入完整框架 |
| Alphalens | 前向收益、IC、分组收益和换手率等经典口径 | 用于指标定义与黄金结果校验 |
| QUANTAXIS | 国内市场数据、因子、异步计算和调度模块划分 | 参考模块边界，不复制其交易与分布式体系 |
| RQAlpha | A股交易规则、费用、撮合和插件机制 | P0不接入，未来回测阶段参考 |
| vectorbt | 向量化组合模拟和参数扫描 | 仅作为后续多因子组合研究参考 |
| MLflow Tracking | Experiment、Run、参数、指标和Artifact模型 | 借鉴实验记录模型，首期自行实现 |
| DuckDB | 直接查询Parquet、过滤和列裁剪 | 用于本地大表查询 |

调研后的技术原则为：

> 采用“Qlib的研究流程骨架 + Alphalens的指标口径 + MLflow的实验记录模型 + DuckDB的本地查询能力”，不直接二次开发某个大型量化系统。

## 六、系统总体设计

### 6.1 架构选择

首期采用“模块化单体 + 独立计算 Worker”，不采用微服务。原因如下：

- 团队规模只有4人，且主要编码工作集中在组长；
- 课程项目用户量和并发量较小；
- 单体结构更容易调试、部署和展示；
- 身份、数据、因子、研究、任务和报告仍按模块划分，后续具备拆分条件；
- 长耗时研究任务由独立 Worker 执行，不阻塞网页请求。

### 6.2 技术架构

```text
┌─────────────────────────────────────────────┐
│              React + TypeScript             │
│  数据集 / 因子库 / 研究任务 / 结果 / 报告   │
└──────────────────────┬──────────────────────┘
                       │ HTTP API
┌──────────────────────▼──────────────────────┐
│                   FastAPI                   │
│ 身份权限 │ 数据版本 │ 因子 │ 实验 │ 报告    │
└──────────────┬────────────────┬─────────────┘
               │                │
       ┌───────▼──────┐  ┌─────▼──────────┐
       │ PostgreSQL   │  │ Redis + Celery │
       │ 元数据与状态  │  │ 队列与任务进度 │
       └──────────────┘  └─────┬──────────┘
                               │
                         ┌─────▼──────┐
                         │   Worker   │
                         │ 因子与检验 │
                         └─────┬──────┘
                               │
                    ┌──────────▼──────────┐
                    │ Parquet + DuckDB   │
                    │ 行情、因子和大结果  │
                    └─────────────────────┘
```

### 6.3 核心实体

下一阶段优先建立以下五个实体：

| 实体 | 作用 |
| --- | --- |
| DatasetVersion | 记录数据范围、来源、校验和、发布日期和文件位置 |
| FactorVersion | 记录因子公式、参数、说明和版本 |
| Experiment | 保存用户选择的数据、因子与研究参数 |
| Run | 记录一次执行的状态、进度、时间和错误信息 |
| Artifact | 索引指标JSON、图表数据、日志和HTML报告 |

一次成功研究的输入和结果不可原地修改；修改参数或重新运行时生成新的实验或Run，以保证结果可追溯。

## 七、因子研究方法

### 7.1 首个演示因子

首个闭环选择20日动量因子：

```text
Momentum(t) = Close(t) / Close(t-20) - 1
```

因子在交易日收盘后形成，最早用于下一交易日收益检验：

```text
ForwardReturn(t) = Close(t+1) / Close(t) - 1
```

这种对齐方式用于避免将未来价格信息错误地用于当期因子判断。

### 7.2 主要检验指标

| 指标 | 含义 |
| --- | --- |
| 覆盖率 | 有效因子观测占应有观测的比例 |
| IC | 每个交易日因子值与下一期收益的Pearson相关系数 |
| Rank IC | 因子排名与收益排名的相关系数 |
| ICIR | IC均值与IC波动率之比 |
| 分组收益 | 按因子从低到高分组后的平均收益 |
| 多空收益 | 最高因子组与最低因子组的收益差 |
| 换手率 | 相邻调仓期证券成员或权重变化程度 |
| 因子相关性 | 不同因子截面值之间的相关程度 |

### 7.3 研究正确性原则

- 原始行情保留未复权价格和复权因子，研究收益使用统一复权口径。
- 因子值与未来收益严格错开，禁止前视偏差。
- 财务指标按实际披露日期生效，不能使用未来才能获得的数据。
- 使用人工小数据和独立脚本建立黄金结果，比较关键指标误差。
- 报告披露样本范围、复权方式、停牌处理和已知偏差。

## 十一、风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 只有队长具备较强编程能力 | 集成工作集中、进度不均 | 责任包独立验收，其他成员承担数据、公式验证和测试材料 |
| 团队量化知识不足 | 指标口径和结论可能错误 | 学习路线、公式评审、黄金数据和开源项目交叉验证 |
| 数据接口限流或失效 | 开发和演示中断 | 提前固化Parquet快照，核心演示完全离线运行 |
| 当前成分股造成幸存者偏差 | 研究结果被高估 | 报告明确披露，历史成分股作为P1功能 |
| 财务数据产生前视偏差 | 研究结论失真 | 按实际披露日期进行Point-in-Time对齐 |
| 功能范围持续扩大 | 无法按期完成 | 冻结P0，新增内容进入P1或P2 |
| Mac和Windows行为不同 | 集成与答辩环境不稳定 | Docker Compose、WSL2、跨平台路径和固定依赖版本 |
| 大型开源框架过度引入 | 学习和部署成本失控 | 只借鉴设计与指标口径，不直接拼装完整平台 |
